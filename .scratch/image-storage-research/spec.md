# Image upload, storage, and CDN options for Tsuki

**Research date:** 2026-08-28  
**Scope:** Public profile avatars and banners for Tsuki (`apps/web` Next.js 16.3, `apps/api` Elysia, Better Auth, Neon Postgres/Drizzle).  
**Source policy:** Product behavior and pricing are based only on first-party documentation or pricing/API pages. Every source link below was accessed 2026-08-28. Prices and quotas are snapshots; re-check them before implementation.

## Recommendation

For the smallest operational surface, use **Cloudflare R2 with server-issued presigned PUT URLs, a custom-domain cache, and an explicit image-processing step**. R2 exposes an S3-compatible API, supports browser-safe presigned `PUT` URLs with content-type restrictions, has free egress, and charges deletes as free operations. A custom domain enables Cloudflare Cache; `r2.dev` is rate-limited and intended for development. ([R2 presigned URLs](https://developers.cloudflare.com/r2/api/s3/presigned-urls/), accessed 2026-08-28; [R2 public buckets](https://developers.cloudflare.com/r2/buckets/public-buckets/), accessed 2026-08-28; [R2 pricing](https://developers.cloudflare.com/r2/pricing/), accessed 2026-08-28.)

R2 is the best default when Tsuki values portability and predictable delivery cost over turnkey media features. R2 is object storage rather than a full image-transformation product; pair it with Cloudflare Images Transformations or a Worker, or preprocess in an application/worker pipeline. Cloudflare Images Transformations can fetch originals from another origin, apply resize/format/quality operations, and cache each unique variant at the edge. ([Cloudflare Images Transformations](https://developers.cloudflare.com/images/optimization/transformations/overview/), accessed 2026-08-28.)

Choose **ImageKit** for the least custom media code, **Cloudinary** for its broader media/DAM ecosystem, and **UploadThing** only when typed Next.js upload ergonomics outweigh the lack of native image transformations and stronger URL/provider dependency. ([ImageKit delivery](https://imagekit.io/docs/core-delivery-features), accessed 2026-08-28; [ImageKit external storage](https://imagekit.io/docs/integration/connect-external-storage), accessed 2026-08-28; [Cloudinary transformations](https://cloudinary.com/documentation/image_transformations), accessed 2026-08-28; [UploadThing files](https://docs.uploadthing.com/working-with-files), accessed 2026-08-28.)

## Detailed findings

### Cloudinary

- **Direct upload:** The Upload Widget supports direct unsigned browser uploads using a cloud name and upload preset without Tsuki's server; signed uploads are available for stronger control. Cloudinary warns that unsigned presets can be discovered and abused, so restrict file types, size, and overwrite behavior. ([Upload Widget](https://cloudinary.com/documentation/upload_widget), accessed 2026-08-28; [Upload API](https://cloudinary.com/documentation/image_upload_api_reference), accessed 2026-08-28.)
- **Transforms/CDN:** Dynamic URLs support resize, crop, automatic format selection, effects, overlays, and other transformations. Results are delivered through a CDN and cached; newly generated derived assets contribute to usage. ([Image transformations](https://cloudinary.com/documentation/image_transformations), accessed 2026-08-28.)
- **Deletion:** `destroy` works by public ID or immutable asset ID. `invalidate` invalidates CDN copies; Cloudinary says propagation can take seconds to minutes, so versioned delivery URLs are preferable for replacements. ([Upload API reference](https://cloudinary.com/documentation/image_upload_api_reference), accessed 2026-08-28; [Invalidate cached media](https://cloudinary.com/documentation/invalidate_cached_media_assets_on_the_cdn), accessed 2026-08-28.)
- **Cost/portability:** The current comparison page describes 1,350 monthly credits and the mixed credit definitions above. Cloudinary also documents copying/browsing assets and customer-storage backup on paid plans, reducing but not removing migration work. ([Cloudinary plan comparison](https://cloudinary.com/pricing/compare-plans), accessed 2026-08-28.)

**Tsuki fit:** Excellent for bounded avatar/banner variants (square crops, responsive widths, WebP/AVIF, face-aware crops) with little backend media code. Persist the returned asset ID/public ID and a provider-neutral purpose; do not make a transformation URL the only canonical value.

### ImageKit

- **Direct upload:** V2 requires the client to obtain a short-lived JWT from an authenticated backend endpoint. The backend signs the upload payload with the private key, which must never be published to the browser; the documented token expiration is less than one hour. ([Upload File V2](https://imagekit.io/docs/api-reference/upload-file/upload-file-v2), accessed 2026-08-28.)
- **Transforms/CDN:** URL transformations cover resize, crop, rotation, effects, overlays, format conversion, smart cropping, and AI operations. ImageKit documents global CDN caching, purge, automatic optimization, optional paid custom domains, and Amazon CloudFront as its default CDN. ([Image transformations](https://imagekit.io/docs/image-transformation), accessed 2026-08-28; [Core delivery features](https://imagekit.io/docs/core-delivery-features), accessed 2026-08-28.)
- **External origin:** ImageKit can proxy S3, Azure Blob, GCS, web-server, and other storage, while originals remain in Tsuki-controlled storage. ([Connect external storage](https://imagekit.io/docs/integration/connect-external-storage), accessed 2026-08-28.)
- **Deletion/cost:** Media API deletion uses `fileId` and private-key authentication. The official plans page advertises a no-time-limit free plan; the current quota snapshot is 20 GB/month bandwidth and 3 GB DAM storage, with Lite at $9/month and Pro at $89/month. Confirm displayed quotas and overage terms at signup. ([Delete File](https://imagekit.io/docs/api-reference/digital-asset-management-dam/managing-assets/delete-file), accessed 2026-08-28; [ImageKit plans](https://imagekit.io/plans/), accessed 2026-08-28.)

**Tsuki fit:** Best managed-service match when Tsuki wants browser upload plus URL variants while retaining the option to move originals to R2/S3. Better Auth authorization must happen before issuing token material, and `fileId` must be persisted.

### UploadThing

- **Direct upload:** `uploadFiles` obtains presigned URLs via Tsuki's backend file router, then uploads directly to storage; the client API exposes progress callbacks. `createUpload` adds pause/resume while the URL remains valid. ([Client API](https://docs.uploadthing.com/api-reference/client), accessed 2026-08-28.)
- **Authorization/metadata:** File routes provide server middleware for authorization and validated JSON input; `onUploadComplete` is intended for persisting uploaded file data. ([File routes](https://docs.uploadthing.com/file-routes), accessed 2026-08-28.)
- **Delivery/access:** Public files use `https://<APP_ID>.ufs.sh/f/<FILE_KEY>` and private files use short-lived signed URLs. UploadThing explicitly says not to use raw storage-provider URLs because provider/bucket placement may change. ([Working with files](https://docs.uploadthing.com/working-with-files), accessed 2026-08-28; [Regions and ACL](https://docs.uploadthing.com/concepts/regions-acl), accessed 2026-08-28.)
- **Deletion/privacy/cost:** `UTApi.deleteFiles` deletes by key or custom ID. Public-read is default; private files and regions are paid-plan features. The current pricing page shows the free 2 GB app, $10/100 GB app, and $25/250 GB usage-based plan; the official pricing announcement says seats, requests, and bandwidth are not separately charged in usage-based pricing. ([UTApi](https://docs.uploadthing.com/api-reference/ut-api), accessed 2026-08-28; [UploadThing pricing](https://uploadthing.com/), accessed 2026-08-28; [Usage-based announcement](https://docs.uploadthing.com/blog/usage-based), accessed 2026-08-28.)

**Tsuki fit:** Good for a fast TypeScript upload UI, but not a single-vendor answer if Tsuki needs generated image variants or stable raw object URLs. Store the file key/custom ID behind a provider-neutral asset record.

### Cloudflare R2

- **Direct upload:** Presigned URLs authorize one operation on one object for 1 second to 7 days. `PUT` URLs can sign a required `Content-Type`; browser use also requires bucket CORS. ([Presigned URLs](https://developers.cloudflare.com/r2/api/s3/presigned-urls/), accessed 2026-08-28; [R2 CORS](https://developers.cloudflare.com/r2/buckets/cors/), accessed 2026-08-28.)
- **Upload size:** Single-part upload is suited to files under roughly 100 MB, with a 5 GiB maximum; multipart supports resumability and objects up to 5 TiB. Profile media fits single-part `PUT`. ([Upload objects](https://developers.cloudflare.com/r2/objects/upload-objects/), accessed 2026-08-28.)
- **Transforms/CDN:** Custom domains use Cloudflare Cache; `r2.dev` is rate-limited and non-production. Cloudflare Images Transformations handles remote-origin optimization and caches each unique parameter combination, while Workers can implement custom processing. ([Public buckets](https://developers.cloudflare.com/r2/buckets/public-buckets/), accessed 2026-08-28; [Images Transformations](https://developers.cloudflare.com/images/optimization/transformations/overview/), accessed 2026-08-28.)
- **Deletion/cost/portability:** Workers, S3 API, Wrangler, and dashboard deletion are supported; `DeleteObject` is free. Standard pricing and free-tier amounts are listed in the comparison table. R2's S3-compatible endpoint works with AWS SDKs, so stable object keys make migration practical. ([Delete objects](https://developers.cloudflare.com/r2/objects/delete-objects/), accessed 2026-08-28; [R2 pricing](https://developers.cloudflare.com/r2/pricing/), accessed 2026-08-28; [R2 S3 API](https://developers.cloudflare.com/r2/api/s3/), accessed 2026-08-28.)

**Tsuki fit:** Best cost/portability baseline for public assets. Elysia must issue presigned URLs and finalize uploads, and Tsuki must choose where resizing/format conversion occurs.

### Amazon S3 + CloudFront

- **Direct upload:** S3 presigned URLs allow browser upload without AWS credentials. The URL is constrained by the signing principal's permissions; an existing object with the same key is replaced, so use collision-resistant keys. ([S3 presigned upload](https://docs.aws.amazon.com/AmazonS3/latest/userguide/PresignedUrlUploadObject.html), accessed 2026-08-28; [S3 presigned URL security](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html), accessed 2026-08-28.)
- **Transforms/CDN:** S3 documents object storage/lifecycle, while CloudFront documents the CDN distribution and S3 Origin Access Control pattern. A resize/format pipeline is a separate design decision. ([What is S3?](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Welcome.html), accessed 2026-08-28; [CloudFront getting started](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/GettingStarted.html), accessed 2026-08-28.)
- **Deletion/cost:** `DeleteObject` permanently removes an unversioned object; versioned buckets create a delete marker unless a version ID is supplied. Pricing varies by region, class, requests, retrieval, and transfer; CloudFront adds separate charges. ([DeleteObject](https://docs.aws.amazon.com/AmazonS3/latest/API/API_DeleteObject.html), accessed 2026-08-28; [S3 pricing](https://aws.amazon.com/s3/pricing/), accessed 2026-08-28; [AWS Pricing Calculator](https://calculator.aws/), accessed 2026-08-28.)

**Tsuki fit:** Use this when Tsuki already operates AWS infrastructure or needs AWS-native IAM, lifecycle, versioning, or compliance. For a small public-avatar/banner workload, it is more moving parts than R2 without a managed image transformation layer.

## Suggested Tsuki integration shape (provider-neutral)

This is an architectural recommendation, not a source-code change.

1. **Authorize upload:** A Better Auth-authenticated Elysia endpoint validates purpose (`avatar`/`banner`), MIME type, byte limit, and ownership. It creates an immutable random key such as `users/{userId}/{assetId}/original` and returns a provider token or presigned `PUT`; never expose a private API key. ([ImageKit upload security](https://imagekit.io/docs/api-reference/upload-file/upload-file-v2), accessed 2026-08-28; [R2 presigned URLs](https://developers.cloudflare.com/r2/api/s3/presigned-urls/), accessed 2026-08-28; [S3 presigned URLs](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html), accessed 2026-08-28.)
2. **Finalize server-side:** Client reports completion; Elysia verifies provider response/object metadata, then writes the asset record and updates the profile. Do not treat a client-supplied URL as proof of ownership.
3. **Persist provider-neutral metadata:** Keep `id`, `userId`, `purpose`, `provider`, `providerKey`/`fileId`, `objectKey`, MIME type, bytes, dimensions, status, and timestamps. Cloudinary needs public ID/asset ID, ImageKit needs `fileId`, and R2/S3 needs the object key. ([Cloudinary Upload API](https://cloudinary.com/documentation/image_upload_api_reference), accessed 2026-08-28; [ImageKit Delete File](https://imagekit.io/docs/api-reference/digital-asset-management-dam/managing-assets/delete-file), accessed 2026-08-28; [R2 Delete objects](https://developers.cloudflare.com/r2/objects/delete-objects/), accessed 2026-08-28.)
4. **Deliver versioned media:** Expose an application-owned media URL or versioned provider URL. Write the new asset, switch the profile pointer, then delete the old asset asynchronously to avoid stale banner/avatar caches.
5. **Bound transformations:** Keep originals private where practical, publish bounded avatar/banner variants, and cap requested dimensions. For R2/S3, generate variants on upload or through a controlled processor rather than accepting arbitrary transformation parameters.
6. **Delete completely:** Profile replacement/account deletion removes the database pointer and enqueues provider deletion. Cloudinary may require CDN invalidation, ImageKit requires `fileId`, UploadThing uses key/custom ID, and S3-compatible storage uses the object key plus version handling when enabled. ([Cloudinary invalidation](https://cloudinary.com/documentation/invalidate_cached_media_assets_on_the_cdn), accessed 2026-08-28; [ImageKit Delete File](https://imagekit.io/docs/api-reference/digital-asset-management-dam/managing-assets/delete-file), accessed 2026-08-28; [UploadThing UTApi](https://docs.uploadthing.com/api-reference/ut-api), accessed 2026-08-28; [S3 DeleteObject](https://docs.aws.amazon.com/AmazonS3/latest/API/API_DeleteObject.html), accessed 2026-08-28.)

## Decision summary

| Priority                                    | Best choice                                      | Why                                                                                                    |
| ------------------------------------------- | ------------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| Lowest cost, portable originals, public CDN | **R2 + custom domain + separate transform step** | S3-compatible, free egress, Standard free tier, and free deletes.                                      |
| Turnkey transformations and optimization    | **ImageKit**                                     | Secure browser token flow, URL transformations, optimization, CDN, purge, and external-origin support. |
| Broadest managed media/DAM feature set      | **Cloudinary**                                   | Mature widget, transformation URL API, CDN, and asset-management APIs.                                 |
| Fastest TypeScript upload integration       | **UploadThing**                                  | Typed routes, presigned browser uploads, progress/resumability, and managed delivery.                  |
| AWS-native platform/compliance              | **S3 + CloudFront**                              | IAM, lifecycle/versioning, standard object API, and AWS-native edge delivery; more components.         |
